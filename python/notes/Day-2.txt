Computer Memory Management — Overview
=========================================
**Memory management** is the process by which a computer system controls and coordinates memory usage among programs and processes.
It ensures **efficient allocation, storage, retrieval, and release** of data in both **primary** and **secondary memory**.


1. Processor (CPU) and Memory Interaction
==============================================
* The **CPU (Central Processing Unit)** executes instructions and processes data.
* It cannot access the **hard disk** directly — data must first be loaded into **RAM**.
* The CPU has small, fast storage areas called **registers** and **cache** to store temporary data.

Levels of Memory in Relation to CPU:

| Memory Type                       | Speed     | Size       | Function                                 |
| --------------------------------- | --------- | ---------- | ---------------------------------------- |
| **Registers**                     | Fastest   | Very small | Store immediate values used by CPU       |
| **Cache**                         | Very fast | Small      | Stores frequently accessed data          |
| **RAM (Main Memory)**             | Fast      | Moderate   | Holds data and programs currently in use |
| **Hard Disk (Secondary Storage)** | Slow      | Large      | Stores data and programs permanently     |

---

2. RAM (Random Access Memory)
================================
* **Volatile memory** — contents lost when power is off.
* Used to **store data and instructions** temporarily while a program is running.
* Divided into:

  * **Static RAM (SRAM):** Faster, used for cache.
  * **Dynamic RAM (DRAM):** Slower, used for main memory.

Functions:
===========
* Holds **OS, applications, and data** currently in use.
* Enables **faster access** than hard disk.
* Helps **CPU work efficiently** by reducing read/write delays.


3. Hard Disk (Secondary Memory)
==================================
* **Non-volatile storage** — retains data even when powered off.
* Used to store:

  * Operating System (OS)
  * Applications
  * User files and data
* Much **slower** than RAM but has **larger capacity**.

Functions:
===========
* Long-term storage of data.
* Supplies data to RAM when needed.
* Stores **swap files** or **virtual memory** when RAM is full.


4. Saving and Loading Data
=============================
Saving:
=========
* When you **save** a file, data from RAM is written permanently to the **hard disk**.
* The OS assigns a **file name and location** on disk.
* The **File Allocation Table (FAT)** or file system index keeps track of the file.

Loading:
=========
* When you **open or load** a program/file:

  1. The OS copies the required data from **hard disk → RAM**.
  2. CPU accesses and executes instructions from **RAM**.
  3. Frequently used data may be moved into **cache** or **registers** for speed.


Python Memory Management Notes
==================================
PRE — Python Runtime Environment
===================================
Definition:
===========
The **Python Runtime Environment (PRE)** is the software environment that supports the execution of Python programs.

Main Components:
=====================
1. **Python Interpreter**

   * Reads and executes the code line by line.
   * Converts source code (`.py`) into bytecode (`.pyc`).

2. **Python Virtual Machine (PVM)**

   * Executes the **bytecode instructions**.
   * Handles memory allocation, garbage collection, and exceptions.

3. **Memory Manager**

   * Allocates memory for Python objects dynamically.
   * Uses **private heap memory**.

4. **Standard Libraries**

   * Provide built-in modules and functions that the program can use at runtime.


2. PVM — Python Virtual Machine
=================================
Definition:
============
The **Python Virtual Machine (PVM)** is the **core engine** that executes the compiled **bytecode** instructions.

Process:
========
1. The Python **compiler** converts `.py` source code → **Bytecode (`.pyc`)**.
2. The **PVM** reads this bytecode instruction-by-instruction.
3. The **PVM executes** them by:

   * Managing **data types**, **objects**, and **references**.
   * Performing **memory allocation** and **garbage collection**.
   * Interacting with the **Operating System**.

## 💾 **3. Memory Management in a Python Program**

Python uses an **automatic memory management system**, handled by:

* The **Python Memory Manager**, and
* The **Garbage Collector (GC)**.


Memory Areas in a Python Program
===================================

| Memory Segment             | Description                                                                                     | Example                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------- |
| **Code Segment**           | Stores compiled bytecode or machine instructions.                                               | Function definitions, class definitions |
| **Stack Segment**          | Used for **function calls, local variables**, and **control flow**. Managed by the interpreter. | Local variables inside a function       |
| **Heap Segment**           | Used for **objects and data** created dynamically (lists, dicts, objects, etc.).                | `x = [1,2,3]`                           |
| **Static / Global Memory** | Stores global variables and static data.                                                        | Module-level variables, constants       |




Command Line Arguments in Python
=================================
1. What Are Command Line Arguments?
Command Line Arguments** are **values passed to a Python program when it is executed from the command prompt (or terminal).
They allow you to **send input data to your Python script directly from the command line**, without modifying the code.

Example:
==========
If you have a Python file named `add.py`:

```python
import sys

a = int(sys.argv[1])
b = int(sys.argv[2])
print("Sum =", a + b)
```

2. How It Works
===============
Python stores command line arguments in a special list called **`sys.argv`** (from the `sys` module).

Structure of `sys.argv`:
==============================
| Index         | Description               | Example (python add.py 5 10) |
| ------------- | ------------------------- | ---------------------------- |
| `sys.argv[0]` | Name of the Python script | `'add.py'`                   |
| `sys.argv[1]` | First argument            | `'5'`                        |
| `sys.argv[2]` | Second argument           | `'10'`                       |

> All command line arguments are **strings by default**, so you must convert them (e.g., using `int()` or `float()`).


3. Why Command Line Arguments Are Required
=============================================
| Reason                             | Explanation                                                                                  |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| **1. To make programs dynamic**    | You can pass different input values each time you run the program, without editing the code. |
| **2. To automate tasks**           | Useful for scripts that run in automation, batch files, or shell scripts.                    |
| **3. To improve usability**        | Allows users to specify files, directories, or options directly from the command line.       |
| **4. For flexible input handling** | Avoids hardcoding input values in the script.                                                |
